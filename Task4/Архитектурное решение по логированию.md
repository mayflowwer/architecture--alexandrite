# Контекст
Для быстрой диагностики инцидентов, связанных с заказами, требуется понимание состояния системы на этапах жизнненного цикла заказа. Для этого предлагается требуется регистрировать события и состояние системы, собирать их и хранить.

# Мотивация
Внедрение логирования позволит лучше понимать, как сработала бизнес-логика в контексте сервисов в продакшен окружение и dev, ускорит разбор инцидентов, увеличит удовлетворенность клиента сервисом.

# Предлагаемое решение
Список данных, которые предлагается логировать доступен на [схеме IT-ландшафта](./jewerly_c4_model.drawio_logging.png) 

Для сбора, хранения и доступа к данным логов предлагается использоватье классический стек ELK:
1) агент сбора данных с api-сервисов FileBeat
2) аккумулирование данных с помощью Logstash
3) хранение и оптимизация поиска данных логирования с помощью ElasticSearch
4) доступ к данным логирования и их визуализации с помощью Kibana

# Политики управления логированием
## Контроль доступа
Логи - данные, которые будут использоваться в работе техническими специалистами - devOps-инженерами, разработчиками - и не должны быть доступны иным пользователям контура компании.
1. Для обеспечения ИБ и контроя доступа к данным требуется закрыть сервис Kibana авторизацией.
2. Необходимо реализовать принцип наименьших привелегий для получения логов сервисов согласно матрице ролей и привилегий:
| Роль пользователя     | Сервис                                               | Доступ |
| DevOps-инженер, админ | Все сервисы, все окружения                           | Все    |
| Разработчик ПО        | В рамках своего сервиса все окружения                | Все    |
| Тестировщик/QA        | В рамках своего сервиса / test-окружение/stage       | Все    |
| Специалист ИБ         | Все сервисы, prod-окружение                          | Все    |

# Контекст
Коммуникация клиентов с системой происходит в контексте приложения Интернет-магазина (Internet Shop). 
Клиенту доступны функции:
- получения списка продуктов(изделий) к наличии
- фильтрация списка украшений по параметрам
- добавления/удаления украшений в корзину магазина
- загрузка 3d-модели изделия собственного дизайна
- получения списка своих заказов
- управления заказом

Получена обратная связь от клиентов, что функции получения списка украшений Интернет-магазина работает с высокой задержкой, что не нравится клиентам и снижает их удовлетворенность сервисом в целом.
Также выявлена деградация производительности базы данных магазина, которая не справляется с нагрузкой на запросы чтени данных. 

Далее с подтвержденными заказами работают операторы системы Mes, которые отвечают за прием заказа в работу и изготовления изделия 
Для работы с заказами оператор выполняет следующие функции:
1) получение список заказов, ожидающих исполнителя (далее - новые заказы)
2) получение списка своих заказов
3) редактирование заказа (изменение статуса, добавление комментариев и проч.) 

Операторы жалуются на общий перфоманс системы Mes, в особенности за долгую загрузку страницы новых заказов.

# Мотивация
Для улучшения пользовательского опыта клиентов Интернет-магазина и операторов Mes предлагается оптимизировать процессы получения данных при помощи внедрения кеширования.
Кеширование часто используемых данных, отображаемых в UI-системах, позволит снизить нагрузку на API и базы данных, что положительно скажется на смежных процессах сервисов.

# Предлагаемое решение
В контексте взаимодействия клиента с Интернет-магазином:
1. Во флоу получения списка продуктов на странице Интернет-магазина:
   1. Внедрить NoSQL базу Redis
   2. Сохранять данные метода GET /products для всех пользователей
   3. Обновлять кеш после каждого изменения количества продукта на складе (update в базе данных магазина) по модели Wtire-Behind (сначала даные пишутся в кеш, далее ассинхронно обновляем базу данных магазина). Это позволит не ждать пока данные успешно запишутся в базу данных, однако потребует тщательной отладки.
2. Во флоу получения списка новых заказов на веб-странице Mes:
   1. Внедрить NoSQL базу Redis
   2. Сохранять данные метода GET /orders для всех пользователей
   3. Обновлять кеш после смены статуса каждого заказа с "MANUFACTURING_APPROVED" на "MANUFACTURING_STARTED", удалять из кеша заказы со стасутом, !=MANUFACTURING_APPROVED
   4. Доработать логику web-приложения Mes, сделав дефолтную страницу/дефолтную фильтрацию получения списка новых заказов.
